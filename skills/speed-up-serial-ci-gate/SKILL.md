## When to Use
单个 self-hosted runner、一个长串行 verify/测试脚本、每个 PR 都在付全量时长的场景。多 runner 可水平扩 job 时不适用。

## Procedure
1. 解析门禁脚本为独立入口清单，复刻原脚本的变量、工作目录与前提（先试跑一个代表入口验证上下文），串行逐项计时得到剖面；与 CI 实测总时长对账，容差按机器噪声与内容差异定，不预设固定百分比（本机示例：macmini 串行 404s vs CI 408s）。计时须记录整批 wall clock，与各入口耗时之和分开。
2. 由剖面耗时分布识别瓶颈（本机示例：top-20 占 90%，最长单测 90s 决定下限）；按机器资源与同机争用情况选并行度起点，实测确认无排队后不加路（本机示例：8=性能核数；未在其它机器验证，属未测预测而非通用规则）。全文区分实测结论与未测预测。
3. 先跑全并行变体抓并发冲突（共享端口/锁/stub 的测试通常快速失败，但不是保证；skip 与 pass 可能同为 exit 0），失败或可疑项进显式串行排除名单并附一行 why。
4. 落地实现：显式数组（并行池+排除名单）、后台 job+wait -n 节流、子 shell 包裹防 exit 逃逸、输出按序回放、任一失败聚合成清单后整体 exit 1；驱动自身退出码与被测检查退出码分开记录，实验结果按 variant 隔离落盘不共用路径。
5. 验证三件套：改前/改后逐入口结果集对比（PASS/FAIL/SKIP 与实际访问目标，计数相同只是必要条件不是充分证据）、失败注入演示聚合红、CI runner 实测新时长；环境前提（bash>=4.3 等）加响亮守卫。
6. 独立跨模型审查计数等价与并发盲区，PR 绿后合并并在票里回写 runner 实测数。
## Pitfalls
- 共享资源冲突通常快速失败，但不是保证：skip 与 pass 可能同为 exit 0，必须按逐入口结果集判别，不能只看总计数与整体退出码。
- 抽取门禁命令做独立计时前必须复刻原脚本变量与工作目录并先试跑一个入口，否则整批秒败且容易误判为测试问题。
- 实验结果按 variant 隔离落盘；共用输出路径会覆盖证据，只剩 stdout 可恢复。
- 并行下驱动退出码正常不代表检查全过；聚合失败退出码后还要用失败注入验证驱动确实会非零退出。
## Verification
1. 改前后逐入口结果集完全一致：每个入口的 PASS/FAIL/SKIP、跳过原因与实际访问目标逐项对比；CHECKS 计数相同只是必要条件，不构成覆盖不变的充分证据。
2. 注入失败演示打印清单且整体非零退出；驱动自身 rc=0 不代表被测检查全过，两层退出码分开断言。
3. runner 实测提速数与本地数同量级，偏差能被机器差异与同机争用解释；性能结论标注实测条件，不外推为通用判据。
